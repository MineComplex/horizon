# Client, game, server, proxy

Horizon is being split into crates with one job each. The goal: the client is the game with a window
(a copy of Minecraft), the server runs worlds headless with a Bukkit-like plugin API, and the proxy is a
Velocity analog.

| Crate | Job |
|---|---|
| `horizon-game` | The game without a window: chunks, world, streaming and generation binding, blocks, items, menus, mobs, motion, saves, the LAN/server side (`lan/`), the world's rules and clock (`world_data`). No wgpu, winit, audio or controllers |
| `horizon-client` | Window, rendering, section meshing (`streaming::WorkerContext`), audio, input, screens; re-exports every `horizon-game` module under its old path |
| `horizon-proxy` | Velocity in Rust ([proxy.md](proxy.md)) |
| `horizon-server` | Today: `server.toml` and the supervisor that runs the game headless ([hosting.md](hosting.md)) |

## Done

1. `horizon-game` holds the lib modules that need no window (moved with `git mv`; `horizon_client::X`
   paths still work).
2. Section meshing is pluggable: `horizon_game::streaming::Streaming<C: MeshContext>`; the client's
   `WorkerContext` builds meshes from block models. Block models, sprites and the mesher are client-only.
3. `Game::world_data` (`horizon_game::world_data::WorldData`): game rules, difficulty, clock, time markers,
   timelines and the command registries, out of the window's `UiState`.
4. `Game::front` (`Frontend` in game.rs): the 84 fields only a window uses (window, renderer, input,
   fog, LOD, camera, sounds, HUD widgets) in one struct, apart from the simulation's.
5. `Game = Sim + Frontend` (`Game` derefs to `Sim`), and about 1260 of its 3070 methods are `impl Sim`:
   the ones that touch neither the window nor a window-only method. This is generated by
   `tools/split_game.py`: it rewrites code all over `game/`, which upstream edits too, so a merge of
   upstream reverts the generated commit, merges, and runs the tool again (about two minutes):

   ```sh
   git revert --no-edit <the last "Split Game into Sim + Frontend" commit>
   git merge upstream/main          # only real conflicts left
   python3 tools/split_game.py && cargo fmt --all
   git commit -am "Split Game into Sim + Frontend (generated: python3 tools/split_game.py)"
   ```

There is no single player in this fork: the client only joins servers. The programs:

- `horizon-client` (players): joins servers only. It refuses `--world`, `--seed`, `--creative`,
  `--test-terrain`, `--benchmark`, `--dedicated` and the world fixtures (`game::Program::Client`), and
  `open_world` fails in it, so no path (title screen, horizon-ctl, quick play) opens a world of its own.
  Open to LAN and `/publish` exist only on an integrated server, which it never starts.
- `horizon-server` (`crates/horizon-server`): the dedicated server, Leaf-style.
- `horizon-dev` (`crates/horizon-client/src/bin/horizon-dev.rs`, never shipped): everything, for the
  harnesses: `--world` on the integrated server thread, the fixtures, `--dedicated`. The tools run it.

The integrated server's code still lives in the shared library for `horizon-dev`; it leaves with step 7.
